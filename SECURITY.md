# Security

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository (Security tab, "Report a vulnerability"). If that is not available to you, open the "Security contact request" issue form (New issue, then "Security contact request"; free-form blank issues are disabled in this repository, so the form is the way in). It files an issue titled `security contact request`, asks for no details, only for a way to reach you privately, and the maintainer will arrange a private channel. A conduct report (`CODE_OF_CONDUCT.md`) uses the same form: type `conduct` in its channel box. Please do not open a public issue for a security problem. Include the version, your platform, and the smallest input that shows it, and leave out your notes and transcripts; the `LANE-ERROR` and `ABORTED` lines can carry a cloud account id or an internal host name from the provider's error, so read them before you paste. One person maintains this: expect an acknowledgement within about a week, not a service level.

## Threat model

**What you are installing.** A Claude Code plugin is fully trusted code: its hook and the scripts the skill tells Claude to run execute with your user's permissions. Read the code (standard library only, about thirty files in `engine/`) before you enable it. The plugin has no network code of its own; all model traffic goes through your `claude` CLI.

**What it protects.**
- Your memory directory. Nothing in it is written except by `memory_dream.py promote --apply` (digest-bound to the staged content, after a fresh snapshot, refused if a note changed since) and `memory_hygiene.py restore --apply`. Everything else reads or writes under the data root (`~/.claude/memory-arborist` by default).
- Against prompt injection in notes and transcripts. The proposal lanes treat both as untrusted data and are `claude --safe-mode --tools ""` children (no built-in tools; `--safe-mode` also disables MCP servers, plugins and hooks for the child, but `claude --help` says admin-managed policy settings still apply). A run aborts if the child's declared tool list is not empty; that compares the list the child reports, it does not observe tool use. Lane output is parsed as JSON only (the verifier, the one model gate, must answer with the whole reply as one JSON object, alone or in one code fence and with no repeated key: an object found inside prose is unusable and makes the run INCOMPLETE, because it could be a line quoted out of a note); every hunk must quote evidence that exists in a digest and match text that exists in the snapshot; a hunk's `reason` must be one plain line of at most 200 characters without instruction-like text or secret shapes; and staged edits live outside the memory directory until you approve them. The report is still text written by a model: the skill tells the session that reads it to treat it as data. A canary with a planted injection checks the lanes end to end.
- The recall judge is weaker than the lanes in one respect: it puts the index into the child's system prompt as plain text and gives the child Read, Grep and Glob under `--permission-mode dontAsk`, so an injected line in the index could ask it to read a file that your own Claude Code permission rules allow. Its answers are kept only as short sanitized excerpts and pass or fail.
- The question wizard's children are tool-less like the lanes (`--tools ""`, same tool-list abort), and nothing they return is trusted. Each candidate is checked against the notes. The quoted evidence must be a literal span of a note. Every key is written in a small whitelisted regex grammar (literal characters, `\d`, `\s`, `.`, simple classes, `|`, groups of plain alternatives with nothing after the group, `?` after a single character, `\d` or `\s` at most twice, and one open-ended repeat, `\d` or `\s` followed by `+` or `*`, only as the last item of an alternative; no lookarounds, anchors, backreferences, counted repeats or nested groups; every alternative carries at least three letters or digits that must match, two of them outside groups), must match that span, and no key may match the question or contradict its own answer. Inside that grammar matching is a few passes over the text, not a power of its length: in two random searches (about 77,000 and about 178,000 accepted keys, six answer shapes of 8,000 characters) the slowest single search took 0.42 seconds; that was measured once on the author's machine and the script is not kept in this repository, so treat it as an observation, not a guarantee, and the judge grades at most the first 8,000 characters of an answer. Two earlier versions of this paragraph claimed a bound that was false; the grammar was rewritten after an independent review showed it. A negative question's key is written by the script, its model-chosen probe words must appear in no note (a partial guard: the notes may still hold the answer in other words), and it may not contain its own answer phrase. Questions, quotes and keys that hold secret shapes, personal data, or control, format, line-separator and invisible characters are dropped. A question may not start with a symbol or contain any of `~` `` ` `` `$` `<` `>` `|` `\` `{` `}`; slashes, dots and ordinary punctuation are allowed, so a question can still name a path or carry instruction text. The proposal is written outside the memory directory with a report that shows model and note text only as JSON strings. `accept` installs exactly the bytes whose SHA-256 prefix you pass, validated as those same bytes, which ties the installation to the file you read; it cannot prove that you read it. An existing question set is copied byte for byte to a backup first. An accepted question later becomes the prompt of a judge child that has Read, Grep and Glob, so read the report: the checks cannot tell a sneaky question from a good one. Keys you write by hand are not held to the wizard's grammar, only to the 8,000-character cut.
- Against leaking secrets in digests: transcripts are reduced to short redacted excerpts, written once, with a cue-word rule: a record that contains a credential word such as password, secret, api key or bearer is dropped whole, whatever its value looks like (about 5% of the text records in the author's own transcripts), and records with secret-shaped values are dropped too.

- The confirmation hook (`engine/memory_confirm_gate.py`) makes Claude Code ask you before `memory_dream.py promote --apply`, `memory_hygiene.py restore --apply` and any `memory_*.py` command given `--allow-secret-shapes`. Claude Code shows that prompt in its default and accept-edits permission modes and an "ask" from a hook beats a settings allow rule; its documentation says it normally reaches you in auto mode too, with exceptions. In a headless run an ask counts as a refusal; in tests on Claude Code 2.1.325 and again on 2.1.326 (ten headless calls on 2026-11-17 and fourteen on 2026-11-18) it was still enforced under bypass-permissions mode (documented as skipping permission prompts), but an interactive bypass session was not tested. Claude Code's `disableAllHooks` setting switches the hook off. The hook matches command text (it reads commands split over lines or carrying quotes, braces, escapes and redirections, in any word order and any case of the script name, as a script or as `-m memory_dream`, and the scripts themselves refuse abbreviated flags), and Claude Code starts it only for a command that carries `--apply` or `--allow-secret-shapes` as plain text, so it does not recognise a command built at run time or disguised by the shell (a variable, an array, `set --` or `xargs` holding the script name or an argument such as `--apply`, also inside an `eval`, a function or a loop: with the words written out in the text those are asked about; a flag split by quotes or a brace expansion; a copied script). Claude Code also runs the hook for a shell command that Claude starts with its Monitor tool (documented for 2.1.314 and later, tried live on 2.1.327; an older version does not). It is a seat belt, not a sandbox: it never denies and never edits, and its failure can only mean no prompt.

**What it keeps on disk.** Under the data root (`<Claude config dir>/memory-arborist/<project>/`, private mode): full snapshots of your notes, redacted digests of idle terminal sessions, recall baselines and your question set, `pinned.txt`, the wizard's proposals (`recall/proposed/`), staged runs and their inputs (`dream/`: a copy of your notes with the proposed edits), the old copy of every note a promote or restore replaced (`archive/`), and a log of what ran, with counts. Nothing is ever deleted by this tool, so the folder grows until you remove old parts yourself (`memory_hygiene.py prune-plan` prints removal lines for old snapshots, `memory_evidence.py purge-plan` the command that removes the whole evidence folder; `archive/`, `dream/` and `recall/proposed/` are removed by hand). Uninstalling the plugin leaves it in place. Treat the data root like your notes and your transcripts: it holds copies of both.

**What it does not protect against.**
- A compromised `claude` binary, model provider account or local user account.
- Secrets the redaction cannot see: rot13 or base85 text, look-alike characters, a bare random string shorter than 32 characters with no cue word, bare UUIDs, bare hex of 32 to 63 characters, and any secret with no recognisable shape. Note text is sent to your provider as it is. Before any lane or judge call, `memory_egress.py` scans the notes the model can read and refuses the run (exit code 4, counts and file names only) when it finds a block-tier secret shape or an entry it cannot scan; the override is the command-line flag `--allow-secret-shapes`, never an environment variable. The scan only knows the shapes in `engine/memory_scan.py`: a plain line such as `password: value` passes (the digest filter is stricter, because a note may legitimately mention a password), and file names are not scanned although the finder prompt carries them. The check runs once per run: the judge's staged arm reads the directory it is given for several minutes, so it should not be a directory a live session is writing to. Each digest also carries the session's working-directory path. Do not run this on a memory directory that holds anything you must not send to your provider.
- Environment you configure. The `MEMORY_ARBORIST_*` variables are trusted configuration. `MEMORY_ARBORIST_PASS_ENV` forwards the named variables, and their values, to the children and from there to the provider. The children run in empty temporary directories, so they do not load a repository's project settings, but they receive `PATH`, `HOME`, `CLAUDE_CODE_USE_BEDROCK`, `AWS_REGION`, `AWS_DEFAULT_REGION` and `AWS_PROFILE` (and any names you list in `MEMORY_ARBORIST_PASS_ENV`) from the session that runs the commands. A project-level settings file in a repository you do not trust can set environment variables for that session (Anthropic's headless documentation says a `claude -p` session applies a project's settings hooks and `env` without a trust dialog), so a hostile `PATH` could change which `claude` is launched; no page says whether `--safe-mode` ignores a project `env` block. Do not run a session in such a repository with this plugin enabled.
- Cost. Each run has per-lane, per-question and total ceilings (the run's default total is $8, the judge's $5), but they are approximate: a failed child counts the cost it printed (one that fails without printing a result counts nothing), a timed-out child is charged its per-call cap (an assumed charge, not billed spend), calls that are already running when a ceiling is reached still finish, but a call waits for the running ones to end while what has been spent plus their per-call caps reaches the ceiling, and is refused only when the money really spent has reached it, so a run can pass the ceiling by less than one per-call cap (and a per-call cap is the child's own estimate, not a guarantee), one writer may pass on at most 5 hunks, and each hunk still gets one paid verifier call before the free grounding runs. Your provider bills you; check the ceilings before raising any limit. A judge question appears in the process list for the duration of its call.
