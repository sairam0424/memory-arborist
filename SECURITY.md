# Security

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository (Security tab, "Report a vulnerability"). Please do not open a public issue for a security problem. Include the version, your platform, and the smallest input that shows it.

## Threat model

**What you are installing.** A Claude Code plugin is fully trusted code: its hook and the scripts the skill tells Claude to run execute with your user's permissions. Read the code (standard library only, about twenty-five files in `engine/`) before you enable it. The plugin has no network code of its own; all model traffic goes through your `claude` CLI.

**What it protects.**
- Your memory directory. Nothing in it is written except by `memory_dream.py promote --apply` (digest-bound to the staged content, after a fresh snapshot, refused if a note changed since) and `memory_hygiene.py restore --apply`. Everything else reads or writes under the data root (`~/.claude/memory-shepherd` by default).
- Against prompt injection in notes and transcripts. The proposal lanes treat both as untrusted data and are `claude --safe-mode --tools ""` children (no built-in tools; `--safe-mode` also disables MCP servers, plugins and hooks for the child, but `claude --help` says admin-managed policy settings still apply). A run aborts if the child's declared tool list is not empty; that compares the list the child reports, it does not observe tool use. Lane output is parsed as JSON only; every hunk must quote evidence that exists in a digest and match text that exists in the snapshot; a hunk's `reason` must be one plain line of at most 200 characters without instruction-like text or secret shapes; and staged edits live outside the memory directory until you approve them. The report is still text written by a model: the skill tells the session that reads it to treat it as data. A canary with a planted injection checks the lanes end to end.
- The recall judge is weaker than the lanes in one respect: it puts the index into the child's system prompt as plain text and gives the child Read, Grep and Glob under `--permission-mode dontAsk`, so an injected line in the index could ask it to read a file that your own Claude Code permission rules allow. Its answers are kept only as short sanitized excerpts and pass or fail.
- The question wizard's children are tool-less like the lanes (`--tools ""`, same tool-list abort), and nothing they return is trusted. Each candidate is checked against the notes. The quoted evidence must be a literal span of a note. Every key is written in a small whitelisted regex grammar (literal characters, `\d`, `\s`, simple classes, `|`, groups of plain alternatives with nothing after the group, `?` after a single character at most twice, and `\d+` only as the very last item; no lookarounds, anchors, backreferences, counted repeats or nested groups; every alternative carries at least three letters or digits that must match, two of them outside groups), must match that span, and no key may match the question or contradict its own answer. Inside that grammar matching is a few passes over the text, not a power of its length: in two random searches (about 77,000 and about 178,000 accepted keys, six answer shapes of 8,000 characters) the slowest single search took 0.42 seconds on one machine, and the judge grades at most the first 8,000 characters of an answer. Two earlier versions of this paragraph claimed a bound that was false; the grammar was rewritten after an independent review showed it. A negative question's key is written by the script, its model-chosen probe words must appear in no note (a partial guard: the notes may still hold the answer in other words), and it may not contain its own answer phrase. Questions, quotes and keys that hold secret shapes, personal data, or control, format, line-separator and invisible characters are dropped. A question may not start with a symbol or contain any of `~` `` ` `` `$` `<` `>` `|` `\` `{` `}`; slashes, dots and ordinary punctuation are allowed, so a question can still name a path or carry instruction text. The proposal is written outside the memory directory with a report that shows model and note text only as JSON strings. `accept` installs exactly the bytes whose SHA-256 prefix you pass, validated as those same bytes, which ties the installation to the file you read; it cannot prove that you read it. An existing question set is copied byte for byte to a backup first. An accepted question later becomes the prompt of a judge child that has Read, Grep and Glob, so read the report: the checks cannot tell a sneaky question from a good one. Keys you write by hand are not held to the wizard's grammar, only to the 8,000-character cut.
- Against leaking secrets in digests: transcripts are reduced to short redacted excerpts, written once, with a cue-word rule: a record that contains a credential word such as password, secret, api key or bearer is dropped whole, whatever its value looks like (about 5% of text records on real transcripts), and records with secret-shaped values are dropped too.

**What it does not protect against.**
- A compromised `claude` binary, model provider account or local user account.
- Secrets the redaction cannot see: rot13 or base85 text, look-alike characters, a bare random string shorter than 32 characters with no cue word, bare UUIDs, bare hex of 32 to 63 characters, and any secret with no recognisable shape. Note text is sent to your provider as it is. Before any lane or judge call, `memory_egress.py` scans the notes the model can read and refuses the run (exit code 4, counts and file names only) when it finds a block-tier secret shape or an entry it cannot scan; the override is the command-line flag `--allow-secret-shapes`, never an environment variable. The scan only knows the shapes in `engine/memory_scan.py`: a plain line such as `password: value` passes (the digest filter is stricter, because a note may legitimately mention a password), and file names are not scanned although the finder prompt carries them. The check runs once per run: the judge's staged arm reads the directory it is given for several minutes, so it should not be a directory a live session is writing to. Each digest also carries the session's working-directory path. Do not run this on a memory directory that holds anything you must not send to your provider.
- Environment you configure. The `MEMORY_SHEPHERD_*` variables are trusted configuration. `MEMORY_SHEPHERD_PASS_ENV` forwards the named variables, and their values, to the children and from there to the provider. The children run in empty temporary directories, so they do not load a repository's project settings, but they copy `PATH` and `HOME` (and the listed names) from the session that runs the commands. A project-level settings file in a repository you do not trust can set environment variables for that session (Anthropic's headless documentation says a `claude -p` session applies a project's settings hooks and `env` without a trust dialog), so a hostile `PATH` could change which `claude` is launched; no page says whether `--safe-mode` ignores a project `env` block. Do not run a session in such a repository with this plugin enabled.
- Cost. Each run has per-lane, per-question and total ceilings (the run's default total is $8, the judge's $5), but they are approximate: a failed child counts the cost it printed (one that fails without printing a result counts nothing), a timed-out child is charged its per-call cap (an assumed charge, not billed spend), workers that are already running can overshoot by their per-lane cap, one writer may pass on at most 5 hunks, and each hunk still gets one paid verifier call before the free grounding runs. Your provider bills you; check the ceilings before raising any limit. A judge question appears in the process list for the duration of its call.

## Supported versions

Only the latest release receives fixes while the project is pre-1.0.
