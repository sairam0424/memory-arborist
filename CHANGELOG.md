# Changelog

All notable changes are listed here. The format follows Keep a Changelog; versions follow Semantic Versioning once 1.0.0 ships. Until then a minor version may change behaviour.

## [Unreleased]

### Added
- First public extraction of the engine: safety net (snapshot, verify, restore, lint, secret scan, compare, log, prune plan), redacted evidence digests, an outside recall judge, tool-less proposal lanes with mechanical grounding, staged runs with digest-bound promote, and a read-only session-start headroom hook.
- Recall-question wizard (`recall/memory_recall_wizard.py`, key grammar in `recall/memory_recall_keys.py`): tool-less children propose questions from the snapshot's notes; every candidate is checked against the notes (literal quote, keys in a safe regex grammar that match the quote and neither the question nor their own answer, absent probe words for negative questions); the proposal and a report are written outside the memory directory, and `accept` installs exactly the bytes whose digest the user passes.
- The recall judge grades at most the first 8,000 characters of an answer, so a key cannot be made to run on an unbounded text.
- Claude Code plugin package (`.claude-plugin/`, `skills/tend/`, `hooks/hooks.json`) and a single-plugin marketplace file.
- `doctor/memory_doctor.py`: a free first-run check of Python, Claude Code (version floors 2.1.139 for the hook and 2.1.169 for the model-backed half, and every flag the engine passes), the login-route variables that are set but not passed to the children (with the exact `MEMORY_ARBORIST_PASS_ENV` line), the memory directory, the data root (same filesystem as the notes) and the first-run files. Its output holds names and counts only. `--live` makes one real call capped at 0.05 USD to prove the login and the output format; `--version` prints the plugin version.
- `memory_dream.py pin --none | --all`: creates `pinned.txt` (create-only, private mode, counts not text), because nothing created it before and the dream run stopped at a dead end on a first run.
- A PreToolUse confirmation hook (`memory_confirm_gate.py`): Claude Code asks the person before `memory_dream.py promote --apply`, `memory_hygiene.py restore --apply` and any `memory_*.py` command given `--allow-secret-shapes`. It never denies and never edits; it cannot ask in bypass-permissions mode and it matches the command text only.
- Every paid command prints an `ESTIMATE` line (calls, cap per call, run ceiling) before its first model call, and the skill is `disable-model-invocation`: it starts only when the person types it, and it asks for a yes before each paid step.
- Community files: issue forms that ask for the doctor output and tell reporters not to paste notes, a pull request template, `SUPPORT.md`, `CODE_OF_CONDUCT.md`, a security contact that works without the Security tab, a statement of what the data root keeps, and a maintainer release procedure (bump the version, `claude plugin tag`, move the `stable` branch that testers add the marketplace from).
- `engine/tests/test_memory_release_packaging.py`: the manifest, the marketplace entry, the hook paths, the skill front matter (including `disable-model-invocation`), the changelog and the README install commands must agree.
- `dev/acceptance/`: a seeded-bad-note acceptance test. A synthetic memory (eight notes the person later contradicted, eight that are still true, four traps: a claim only an assistant made, an instruction planted in a note, a topic merely mentioned) and matching synthetic sessions run through the real pipeline; `run_seeded.py --live` reports how many stale notes were fixed, missed or wrongly edited and whether the planted instruction was followed. Without `--live` nothing is sent. Its tests use a scripted model, so they prove the harness, not a real model's score. Live results (Sonnet 5.5 through Bedrock, two runs of about $0.38): 8 of 8 stale facts found, 10 of 10 accepted hunks correct, 0 stray edits, the planted instruction not followed (in the second run it sits inside a stale note that a writer must read: the first fixture put it in a note nobody edited, so no model ever saw it), 5 notes fixed and 3 deferred by the 10-hunk cap, 2 overreaching hunks rejected by the verifier. The scorer counts an index line that carries the new value as a good hunk and a hunk deferred past the cap as deferred, not missed (the first version of the scorer got both wrong and under-reported the run).
- Release guard test that fails when a home path, or a word from the maintainer's private deny-list (kept in a git-ignored file, not in the repository), appears in the content or the name of any non-binary file (LICENSE, NOTICE and .gitignore included).

### Changed
- Model choices are provider-neutral aliases (`sonnet`, `haiku`) overridable with `MEMORY_ARBORIST_LANE_MODEL` and `MEMORY_ARBORIST_JUDGE_MODEL`.
- Children receive a fixed short environment plus the names listed in `MEMORY_ARBORIST_PASS_ENV`.
- The lint tripwire now only warns when the markdown file count drops below the last snapshot's (`memory-shrink-tripwire`).
- The evidence builder's run marker is `MEMORY-ARBORIST-RUN`.

- `memory_egress.py`: a gate in front of every call that sends note text to the provider. A fresh scan of the notes the model can read refuses the run (exit 4) on a block-tier secret shape or an unscannable entry; `--allow-secret-shapes` overrides it for one run.
- Staging refuses a dream edit that adds a YAML hazard to a note's name or description (`yaml-*` findings), counted per file so a hazard the snapshot already had never blocks.
- At most 5 hunks per writer reach the paid verifier; a failed child's printed cost is counted, and a timed-out child is charged its per-call cap.
- Scanner: GitHub `gho_`/`ghu_`/`ghr_`, Stripe `rk_` and `sk_org_`, Slack `xapp-` and `xoxe-`, OpenAI project, service-account and admin keys, AWS `ABIA`/`ACCA` ids, database schemes `postgresql`, `mongodb+srv`, `rediss`, `mysqlx`, and the Bearer scheme with the RFC 6750 characters (other casings need a digit).
- `CLAUDE_CONFIG_DIR` is followed (the data root moves with it).
- The override flag cannot be given as an argparse abbreviation; a failed child that reports a tool still aborts the run; an absurdly large cost in a result is ignored instead of crashing; the dream run's temporary folder and the judge's are removed with the run; the Anthropic and Stripe key patterns are anchored on the left; database URLs with a `+driver` suffix are matched; a description emptied to `""` or `''` counts as missing.
- Test fixtures that look like credentials are assembled at runtime everywhere; the release guard now scans the repo's own source with the repo's own scanner and refuses the synthetic fake body as one piece, because an external secret scanner flagged it.
- Mutation harnesses refuse to run on a red baseline and report ambiguous patterns; 36 more mutants.

### Fixed
- `dream/memory_dream_canary.py --help` and a mistyped option used to start a paid run; the canary now parses its arguments before it creates anything.
- The evidence builder picks the newest idle sessions first (it took the oldest, so most proposals were rejected as older than the notes), skips a session nobody typed in (`skipped_no_user`), and says in plain words what it left out: sessions by entrypoint name (`sdk-py=574`, an editor, a desktop app) with an opt-in `--include-entrypoint NAME`, and typed records dropped because they carry a key this tool does not know. Names from a transcript are cleaned before they are printed.
- Fixes from an independent pre-beta review (six lenses, each finding re-checked by a skeptic, 61 findings, 59 confirmed, none a blocker): a failed or unusable verifier answer now makes a run INCOMPLETE; the confirmation hook reads commands split over lines or carrying quoted separators and `promote`/`restore` refuse abbreviated flags; the doctor prints the project folder as `<project>` (it spelled the working directory path), checks that pinned lines match the index, refuses a data root inside the notes and watches the gateway variables; `pin --all` pins every non-blank line; the evidence build says when the 512 KiB cap leaves newer sessions without a digest and why a build wrote nothing, bounds its unknown-key counter and refuses sdk-* opt-ins; the wizard exits 5 when batches failed; the judge has `--show-failed`; the documentation was corrected where it was false or stale (auto mode, the update command, the data-root inventory, the doctor's working directory) and ten rows of docs/PROVENANCE.md were re-sourced after a re-check of all 130 against the live pages.
- Failures look like failures. A dream run in which model calls failed used to exit 0 and write "all clean"; it now prints `INCOMPLETE`, puts a banner at the top of `report.md` and exits 5. A failed child is reported with the first line it printed ("claude exited with 1: Not logged in") instead of a bare number (a line that mentions a credential is withheld, with a hint to read it yourself). The recall judge stops after 6 failed calls when none has answered, and prints `TOOLS ok=` only once a child really answered. The dream run now looks for `pinned.txt` before the first paid call instead of after the lanes. A child whose JSON output has no tool list now stops the run with an explanation (this Claude Code version may print a different format) instead of "reported tools None".
