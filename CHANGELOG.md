  - The confirmation hook: a quoted string inside `$( )` or backticks inside double quotes (`--dir "$(cd "/srv/R&D" && pwd)"`) hid `--apply` from the scan, an escaped space or `;` followed by `#` was read as a comment, a `)` inside `${ }` or a `case` arm ended a `$( )` early, `python3 -m memory_dream`, an upper-case script name and the script given last (`python3 - promote RUN --apply < memory_dream.py`) were not recognised, a read error discarded what had been read, and the scan had no size bound. The rules that start the hook match the flags `--apply` and `--allow-secret-shapes` instead of order-dependent patterns on the script name: a first live run showed that Claude Code leaves redirections out when it matches a rule, so a name that appears only as `< memory_dream.py` could not match. Still not covered: the Monitor tool (the hook is attached to Bash only), and a flag disguised by quote splitting or brace expansion.
  - The doctor: a Claude config directory that is not `~/.claude` is shown as `<custom path>`; a question file that does not load shows `line N: <kind of problem>` and never quotes the line; `--live` scrubs the model string (an inference-profile ARN carried an account id) and says that the recall judge's own model was not tried; text a child process printed has secrets withheld and paths outside the home folder replaced; one byte that is not UTF-8 no longer ends the run with a traceback; a regex such as `a{4294967296}` no longer crashes the doctor or the judge's loader; a missing notes folder no longer hides the data-root and first-run checks.
  - Promote, judge and lanes: any failure after the first replaced note is a recorded partial promote with the way back on screen, and the loser of two concurrent promotes is told so; the judge checks `--baseline` and `--save` before its first paid call and rejects counts of zero or less in `--repeat`, `--limit`, `--workers`, `--max-hunks` and `--max-notes` (`--min` takes zero to mean no floor); a dream run's paid proposals are kept when a hunks file of the same second exists; a reply with an unclosed ``` fence followed by a long run of blank lines can no longer hang the parent, and a verifier answer that quotes a verdict cannot flip it.
  - Privacy and restore: a card number followed by an expiry date or a security code is masked in digests (the whole run of digits failed the Luhn check and passed); a restore whose archive folder cannot be made names the staged copy it left; a full digest folder no longer says "no digest was written"; a hunk whose new text is over 6,000 characters is refused before the token scan (20,000 characters of dotted words cost 43 s).
  - Release tools: `check_history.py` reads every object a ref reaches (tags of blobs and trees, nested tags, extra commit headers, side branches, submodule names), ignores replace refs, graft files and an inherited `GIT_DIR`, and exits 2 when it cannot be complete (missing objects, shallow or partial clone, no commits, a list of only short entries); `rewrite_history.py` replays commits and tags byte for byte, refuses headers it cannot replay, takes no tag nobody asked for, builds in a hidden folder next to the destination and verifies tags, refs and unreachable objects before moving it into place.
  - A second round by four fresh read-only reviewers (the hook by differential fuzz against bash 5.3 and zsh 5.9, the release tools one by one, the doctor and engine fixes of the first round) found and fixed: a comment ending in a backslash, `$'...'` strings, `-mmemory_dream`, a script piped to `python3 -` (also with options, `/dev/stdin`) in the hook, plus a quadratic pattern of my own that the reviewers measured (now linear and covered by timing tests); a card number after a date or order id, folder names with spaces, colon lists, `file:` URLs, `~/` and `./` paths and MCP tool names in the doctor's child text, an empty stderr reported as a credential, `--live` outside the per-check guard, a deeply nested question regex, and restore failure paths that did not name the staged copy; and, in the release tools, late `parent`/`object` header lines, look-alike Unicode, UTF-16 and Latin-1 files, an unborn `HEAD`, empty directory names, a free-text `Signed-off-by:` line passing `--allow-identity`, `--repo` pointing inside a repository, a word list numbered by form feeds, `--ref` read as a tag or an option, a destination inside the source, a run killed by a signal that left a copy of the dropped history, reflogs naming the operator, and `GIT_TEMPLATE_DIR` or `GIT_CONFIG_*` copying files and running hooks inside the clean destination.
  - A third verification pass (four fresh read-only lanes, a skeptic per finding; fixed test first and mutation-checked on copies): a promote that stopped halfway shows its `PARTIAL` line and the restore command before it writes its marker and log, and a marker or log that cannot be written is a message (the notes WERE replaced, do not promote the run again, the snapshot to restore from) or a note, never a traceback; a `promoted.json` that is empty or damaged is no longer read as "already promoted"; the recorded reason of a partial promote no longer says "nothing was replaced"; the judge's `--save` preflight follows links and file modes (an unwritable file, a dangling link and a link loop are refused before the first paid call) and a write that still fails says what was lost; a promote records its marker (finished or partial) before it releases the lock, so a second promote of the same run that lost the race finds the marker and says so instead of recording a failure of its own; a closed output pipe on the `PROMOTED` line sends the line to the error stream and still writes the marker; a live note that is missing while the copies are prepared is a message, not a raw errno; the verifier's reply check is linear (a 200,000-character reply of small objects cost about 22 s of CPU); count options take ASCII digits only; two dream-harness mutants that had silently stopped running now run, and the new fixes have mutants of their own; the doctor, README, SECURITY and the skill are corrected where they were stale or too strong (hook limits, the token figure, the typical cost, the doctor's pointer into the skill).
  - Left open on purpose (owner decisions or minor): a data root on another filesystem is still a WARN; the cost ceilings can be passed by up to workers times the per-call cap (SECURITY says so now); the doctor's login watch list still has gaps (45 names, 23 of them without a public source); several wall-clock assertions fail under heavy load; Ctrl-C between two replaced notes leaves no marker (a second promote refuses because the notes changed since the snapshot, and the pre-promote snapshot is the way back); the verifier's answer may be one JSON object quoted inside prose (two different objects are unusable), and requiring the whole reply to be that object would make more runs INCOMPLETE, so that stays an owner decision.

### Added
- `dev/release/check_history.py`: checks every revision of a repository against the maintainer's private word list however a word was written (split string fragments, other case, punctuation between parts, file names, commit and tag messages, author lines), prints entry numbers, counts and short commit ids and never a word, and can allow one identity in commit metadata. The old `git log -p | grep -f` check could not see split fragments. 62 tests, run in CI.
- `dev/release/rewrite_history.py`: rebuilds a repository's history as a new root plus a replay of every later commit in a fresh repository, keeping each commit's tree, authors, dates and message and recreating chosen tags, so the early commits that must not be published are not in the result (not even as unreachable objects). It refuses merges, signed commits and tags on dropped commits, never changes the source, and verifies its own output. 72 tests, run in CI.

## [0.1.1] - 2026-11-17

0.1.0 was tagged on 2026-11-16 but nobody installed it, and its skill text carried a defect that only a real run shows: Claude Code expands `$1`-style placeholders inside skill text, so every dollar figure in it reached the model mangled. 0.1.1 replaces it. It also carries the fixes from a first-tester run: a live session from the 0.1.0 tag archive, then ten lanes against a fake `claude` (stray bytes, malformed results, a failure at each stage, a promote that fails halfway), with every finding re-run by a second tester.

### Fixed
- Skill and README text: every dollar figure in the skill is written "N USD" (a test now fails on the pattern); the skill says where each script lives; the safety-net step runs `lint` before `snapshot` because the shrink tripwire compares with the previous snapshot and could never fire after a new one; it explains a `REGRESSIONS` hit on a fact the run itself changed, the wizard's exit 5, the canary's cost and consent, and to start a second round at step 1. The README's steps are numbered like the skill's, its undo step shows the restore command, and it says what `MEMORY_ARBORIST_HOME` moves.
- Misbehaving model calls: one non-UTF-8 byte from a child ended a paid run with no results, and now the runners decode with replacement characters; a tool list holding a non-string, or deeply nested output, is reported like any malformed result instead of crashing; `--total-max-usd nan` (or 0, or a negative number) switched a ceiling off, and every cost limit now needs a finite number above zero; a staged check in which a question that passed at baseline errored printed `REGRESSIONS n=0` and exited 0, and now prints `UNVERIFIED n=..`, says INCOMPLETE and exits 5; an AWS account id or role ARN in a child's error is replaced before it is printed; the wizard's report starts with the INCOMPLETE banner when batches failed and its `COVERAGE` line adds `notes_covered`.
- Promote and restore: a promote that failed halfway left the next one saying only "already promoted", and now it says "already partly promoted", names the pre-promote snapshot and prints the restore command; one that failed before replacing any note no longer burns the staged run (it says NOTHING was replaced and can be retried); a refused `--apply` no longer prints "replacing ..." lines; two promotes of one run at once are explained instead of dying on a raw errno; promoting or previewing an INCOMPLETE staged run prints a WARNING; restore prints file names safely, and a failed archive names the staged copy and says the note is untouched; the dream run warns, before its first paid call, when the live notes differ from the snapshot it is about to use (a second round after a promote).
- The confirmation hook: `&>`, `>&`, `<&`, `>|` and `${VAR:-a;b}` no longer split a command (so the flag stays with the script name), a backslash-newline joins the lines as bash does, a comment is skipped, and when it cannot read a command with confidence (a here-document, an unclosed quote) the hook judges the whole text and asks if the gated words are in it, and it asks outright when its input fills the read limit; it waits 3.5 s for its input instead of 1 s. Every script prints an unencodable character as an escape instead of ending with a `UnicodeEncodeError`.
- The doctor: it loads the question file the way the judge does (25 junk lines used to pass), fails when the data root is blocked by a file, read-only or short of the 2 GB the snapshot needs, reads a `pinned.txt` that starts with a byte-order mark, keeps one unreadable file from hiding the other checks, says "did not answer within 20 seconds" or "could not be started" instead of an invented exit code, shows any path outside the standard folders as `<custom path>`, replaces cloud account ids in a child's error, and warns when `--live` cost more than its cap.
- The evidence builder and the secret scan: a digest with a relative or Windows-style cwd or an impossible clock time was written and then rejected by the builder's own verify step, so the builder now normalises both and checks a digest before writing it (`skipped_invalid`, with a NOTE); `verify`, grounding and the dream run name the first files at fault (`VERIFY-BAD first=...`); a folder that is already full no longer parses every transcript, and its NOTE says "up to N sessions"; long reads print `BUILD-START` or `SCAN-START` on stderr; a note over the 50 MiB scan limit is reported as "larger than the 50 MiB scan limit, not scanned" instead of "unreadable file: ValueError", `snapshot` prints a WARN that it was not scanned and that the paid steps will refuse it (exit 4) until it is shrunk, and the refusal says to shrink it.

### Added
- An issue form, "Security contact request" (`.github/ISSUE_TEMPLATE/security_contact.yml`), because blank issues are disabled and the old "open an issue" route could not be used; it asks for no details.
- `memory_evidence_verify.py` (the digest verification, moved out of `memory_evidence.py`, which had reached the 500-line limit), `memory_common.safe_stdio()`, and 94 new tests (the five suites went from 1,206 to 1,300): gate forms, safe stdio, doctor checks, evidence and oversize notes, promote edges, child robustness, release docs.

## [0.1.0] - 2026-11-16

Tagged as the first invite-only beta tag; never installed by anyone. Superseded by 0.1.1.

### Added
- First public extraction of the engine: safety net (snapshot, verify, restore, lint, secret scan, compare, log, prune plan), redacted evidence digests, an outside recall judge, tool-less proposal lanes with mechanical grounding, staged runs with digest-bound promote, and a read-only session-start headroom hook.
- Recall-question wizard (`recall/memory_recall_wizard.py`, key grammar in `recall/memory_recall_keys.py`): tool-less children propose questions from the snapshot's notes; every candidate is checked against the notes (literal quote, keys in a safe regex grammar that match the quote and neither the question nor their own answer, absent probe words for negative questions); the proposal and a report are written outside the memory directory, and `accept` installs exactly the bytes whose digest the user passes.
- The recall judge grades at most the first 8,000 characters of an answer, so a key cannot be made to run on an unbounded text.
- Claude Code plugin package (`.claude-plugin/`, `skills/tend/`, `hooks/hooks.json`) and a single-plugin marketplace file.
- `doctor/memory_doctor.py`: a free first-run check of Python, Claude Code (version floors 2.1.139 for the hook and 2.1.169 for the model-backed half, and every flag the engine passes), the login-route variables that are set but not passed to the children (with the exact `MEMORY_ARBORIST_PASS_ENV` line), the memory directory, the data root (same filesystem as the notes) and the first-run files. Its output holds names and counts only. `--live` makes one real call capped at 0.05 USD to prove the login and the output format; `--version` prints the plugin version.
- `memory_dream.py pin --none | --all`: creates `pinned.txt` (create-only, private mode, counts not text), because nothing created it before and the dream run stopped at a dead end on a first run.
- A PreToolUse confirmation hook (`memory_confirm_gate.py`): Claude Code asks the person before `memory_dream.py promote --apply`, `memory_hygiene.py restore --apply` and any `memory_*.py` command given `--allow-secret-shapes`. It never denies and never edits, and it matches the command text only (SECURITY.md says what was and was not observed in auto and bypass-permissions modes).
- Every paid command prints an `ESTIMATE` line (calls, cap per call, run ceiling) before its first model call, and the skill is `disable-model-invocation`: it starts only when the person types it, and it asks for a yes before each paid step.
- Community files: issue forms that ask for the doctor output and tell reporters not to paste notes, a pull request template, `SUPPORT.md`, `CODE_OF_CONDUCT.md`, a security contact that works without the Security tab, a statement of what the data root keeps, and a maintainer release procedure (bump the version, `claude plugin tag`, move the `stable` branch that testers add the marketplace from).
- `engine/tests/test_memory_release_packaging.py`: the manifest, the marketplace entry, the hook paths, the skill front matter (including `disable-model-invocation`), the changelog and the README install commands must agree.
- `dev/acceptance/`: a seeded-bad-note acceptance test. A synthetic memory (eight notes the person later contradicted, eight that are still true, four traps: a claim only an assistant made, an instruction planted in a note, a topic merely mentioned) and matching synthetic sessions run through the real pipeline; `run_seeded.py --live` reports how many stale notes were fixed, missed or wrongly edited and whether the planted instruction was followed. Without `--live` nothing is sent. Its tests use a scripted model, so they prove the harness, not a real model's score. Live results (the lanes' default `sonnet` alias through Amazon Bedrock, whose resolved model id was not recorded; two runs of about $0.37 and $0.39): 8 of 8 stale facts found, 10 of 10 accepted hunks correct, 0 stray edits, the planted instruction not followed (in the second run it sits inside a stale note that a writer must read: the first fixture put it in a note nobody edited, so no model ever saw it), 5 notes fixed and 3 deferred by the 10-hunk cap, 2 overreaching hunks rejected by the verifier. The scorer counts an index line that carries the new value as a good hunk and a hunk deferred past the cap as deferred, not missed (the first version of the scorer got both wrong and under-reported the run).
- Release guard test that fails when a home path, or a word from the maintainer's private deny-list (kept in a git-ignored file, not in the repository), appears in the content or the name of any non-binary file (LICENSE, NOTICE and .gitignore included).

### Changed
- Model choices are provider-neutral aliases (`sonnet`, `haiku`) overridable with `MEMORY_ARBORIST_LANE_MODEL` and `MEMORY_ARBORIST_JUDGE_MODEL`.
- Children receive a fixed short environment plus the names listed in `MEMORY_ARBORIST_PASS_ENV`.
- The lint tripwire now only warns when the markdown file count drops below the last snapshot's (`memory-shrink-tripwire`).
- The evidence builder's run marker is `MEMORY-ARBORIST-RUN`.

- `memory_egress.py`: a gate in front of every call that sends note text to the provider. A fresh scan of the notes the model can read refuses the run (exit 4) on a block-tier secret shape or an unscannable entry; `--allow-secret-shapes` overrides it for one run.
- Staging refuses a dream edit that adds a YAML hazard to a note's name or description (`yaml-*` findings), counted per file so a hazard the snapshot already had never blocks.
- At most 5 hunks per writer reach the paid verifier; a failed child's printed cost is counted, and a timed-out child is charged its per-call cap.
- Scanner: GitHub `gho_`/`ghu_`/`ghr_`, Stripe `rk_` and `sk_org_`, Slack `xapp-` and `xoxe-`, OpenAI project, service-account and admin keys, AWS `ABIA`/`ACCA` ids, database schemes `postgresql`, `mongodb+srv`, `rediss`, `mysqlx`, and the Bearer scheme with the RFC 6750 characters (other casings need a digit).
- `CLAUDE_CONFIG_DIR` is followed (the data root moves with it).
- The override flag cannot be given as an argparse abbreviation; a failed child that reports a tool still aborts the run; an absurdly large cost in a result is ignored instead of crashing; the dream run's temporary folder and the judge's are removed with the run; the Anthropic and Stripe key patterns are anchored on the left; database URLs with a `+driver` suffix are matched; a description emptied to `""` or `''` counts as missing.
- Test fixtures that look like credentials are assembled at runtime everywhere; the release guard now scans the repo's own source with the repo's own scanner and refuses the synthetic fake body as one piece, because an external secret scanner flagged it.
- Mutation harnesses refuse to run on a red baseline and report ambiguous patterns; 36 more mutants.

### Fixed
- `dream/memory_dream_canary.py --help` and a mistyped option used to start a paid run; the canary now parses its arguments before it creates anything.
- The evidence builder picks the newest idle sessions first (it took the oldest, so most proposals were rejected as older than the notes), skips a session nobody typed in (`skipped_no_user`), and says in plain words what it left out: sessions by entrypoint name (`sdk-py=574`, an editor, a desktop app) with an opt-in `--include-entrypoint NAME`, and typed records dropped because they carry a key this tool does not know. Names from a transcript are cleaned before they are printed.
- Fixes from an independent pre-beta review (six lenses, each finding re-checked by a skeptic, 61 findings, 59 confirmed, none a blocker): a failed or unusable verifier answer now makes a run INCOMPLETE; the confirmation hook reads commands split over lines or carrying quoted separators and `promote`/`restore` refuse abbreviated flags; the doctor prints the project folder as `<project>` (it spelled the working directory path), checks that pinned lines match the index, refuses a data root inside the notes and watches the gateway variables; `pin --all` pins every non-blank line; the evidence build says when the 512 KiB cap leaves newer sessions without a digest and why a build wrote nothing, bounds its unknown-key counter and refuses sdk-* opt-ins; the wizard exits 5 when batches failed; the judge has `--show-failed`; the documentation was corrected where it was false or stale (auto mode, the update command, the data-root inventory, the doctor's working directory) and ten rows of docs/PROVENANCE.md were re-sourced after a re-check of all 130 against the live pages.
- Failures look like failures. A dream run in which model calls failed used to exit 0 and write "all clean"; it now prints `INCOMPLETE`, puts a banner at the top of `report.md` and exits 5. A failed child is reported with the first line it printed ("claude exited with 1: Not logged in") instead of a bare number (a line that mentions a credential is withheld, with a hint to read it yourself). The recall judge stops after 6 failed calls when none has answered, and prints `TOOLS ok=` only once a child really answered. The dream run now looks for `pinned.txt` before the first paid call instead of after the lanes. A child whose JSON output has no tool list now stops the run with an explanation (this Claude Code version may print a different format) instead of "reported tools None".
